# SecureAuth v0.1 测试用例表

用于 T6.2 真机矩阵（计划 §4.2），每台设备逐条执行。P0 必须全部通过才能发布；P1 失败需记录 issue 并评估。

## 执行约定

- 安装 CI 产出的 APK（debug 用于功能验证；T7 前用 release 复测 P0 安全项）
- 全程开启**飞行模式**（计划 §4.4）
- 二维码使用 `testdata/qr/`（显示在第二块屏幕上，或存入相册用于“从图片识别”）
- 验证码与 `oathtool` 交叉核对（命令见 `testdata/qr/README.md`）
- 结果记录：设备型号 / 系统版本 / `SDK_INT` / 是否 StrongBox / 每条用例的 通过·失败·不适用

## 自动化覆盖

以下已由自动化测试覆盖，真机上只做抽查：

| 范围 | 测试 | 触发 |
|---|---|---|
| HOTP / TOTP / Base32 / URI 解析 / 加解密 / Vault / PIN 退避 | `:core` 单元测试（覆盖率 ≥ 80%） | 每次推送 |
| 权限白名单、导出组件、`allowBackup`、`dataExtractionRules`、非 debuggable | `scripts/check-apk.sh` | 每次推送 |
| Keystore 加解密、Vault 落盘为密文、重启后数据仍在 | `KeystoreAeadCipherTest`、`DataStoreVaultRepositoryTest` | 模拟器 API 26 / 35，手动或夜间 |
| 设计 §50.8 三条界面路径；数据目录无明文；Logcat 无测试 Secret | `AccountFlowTest` | 同上 |

## 1. 首次启动与锁

| ID | 优先级 | 步骤 | 预期 |
|---|---|---|---|
| L-01 | P0 | 全新安装后首次打开 | 显示风险提示；未勾选“我已了解”时“继续”不可点 |
| L-02 | P0 | 设置 PIN：输入 5 位；输入两次不一致；输入 6 位一致 | 前两次报错并要求重输；最后进入空账号列表 |
| L-03 | P0 | 点“立即上锁”，输错 PIN 4 次，第 5 次再错 | 前 4 次提示错误次数；第 5 次起进入 30 秒等待 |
| L-04 | P0 | 在退避等待中强制停止 App 再打开 | 仍需等待剩余时间（退避重启不清零） |
| L-05 | P0 | 设置中开启生物识别（需先验证一次），上锁 | 锁屏自动弹出生物识别；成功即解锁；点“使用 PIN”回到 PIN |
| L-06 | P1 | 设备未录入生物识别 | 设置中开关不可用并显示原因；锁屏只有 PIN |
| L-07 | P0 | 自动上锁设为“30 秒”，切到后台 40 秒再回来 | 需要解锁；后台 10 秒内回来则不需要 |
| L-08 | P0 | 自动上锁设为“立即”，按 Home 再回来 | 需要解锁 |
| L-09 | P0 | 解锁后在最近任务中划掉 App，再打开 | 必须重新解锁 |
| L-10 | P0 | 开发者选项“不保留活动”打开，切后台再回来（进程死亡恢复） | 必须重新解锁，不显示任何账号 |
| L-11 | P1 | 修改 PIN：当前 PIN 错误 / 正确 | 错误时提示；正确时提示已修改，新 PIN 可解锁、旧 PIN 不可 |
| L-12 | P1 | 锁屏“忘记 PIN？” → 清除全部数据 | 二次确认后回到首次启动引导；原账号全部消失 |

## 2. 添加账号

| ID | 优先级 | 步骤 | 预期 |
|---|---|---|---|
| A-01 | P0 | 扫描 `01_totp_basic` | 进入确认页，显示服务 / 账号 / TOTP / SHA1 / 6 位 / 30 秒；添加后验证码与 `oathtool` 一致 |
| A-02 | P0 | 首次扫码时拒绝相机权限；再次进入并选择“不再询问” | 显示说明；第二次显示“打开系统设置”按钮并能跳转 |
| A-03 | P0 | 扫描 `02_hotp_counter` 并添加 | HOTP，计数器 0，不显示验证码直到点“生成” |
| A-04 | P0 | 依次扫描 `03`–`07`、`11`–`13` | 结果与 `testdata/qr/README.md` 预期一致 |
| A-05 | P0 | 扫描 `08`、`09`、`10` | 显示对应错误提示，相机继续扫描，不崩溃 |
| A-06 | P0 | 再次扫描 `01_totp_basic` | 确认页提示“该账号可能已存在” |
| A-07 | P0 | 从图片识别：选择相册中的 `01_totp_basic.png` | 进入确认页 |
| A-08 | P1 | 从图片识别：选择一张没有二维码的照片 | 提示“图片中没有找到二维码” |
| A-09 | P0 | 手工添加：密钥粘贴 `JBSW Y3DP EHPK 3PXP`（含空格、小写亦可） | 可添加，验证码与 `oathtool --totp -b JBSWY3DPEHPK3PXP` 一致 |
| A-10 | P1 | 手工添加：密钥含 `0`/`1`/`8`；服务名与账号都空；位数 5 | 分别显示对应错误，不进入确认页 |
| A-11 | P1 | 手工添加中旋转屏幕 | 已填内容不丢失 |
| A-12 | P0 | 在确认页按 Home，等待超过自动上锁时间后回来并解锁 | 回到账号列表，确认页内容已清空，未添加该账号 |

## 3. 使用验证码

| ID | 优先级 | 步骤 | 预期 |
|---|---|---|---|
| U-01 | P0 | 观察 TOTP 卡片 30 秒以上 | 倒计时每秒递减，周期切换时验证码更新 |
| U-02 | P0 | 点 TOTP“复制”，粘贴到任意输入框；等待 30 秒后再粘贴 | 首次粘贴为当前验证码；30 秒后剪贴板已清空。Android 13+ 剪贴板预览不显示内容 |
| U-03 | P0 | HOTP 点“生成” 3 次 | 计数器 1、2、3；验证码依次为 RFC 4226 的 755224、287082、359152 |
| U-04 | P0 | HOTP 生成后点“复制”若干次 | 计数器不变 |
| U-05 | P0 | HOTP 生成后立即强制停止 App，重新打开并解锁 | 计数器保持生成后的值（先持久化后显示） |
| U-06 | P1 | 搜索框输入服务名的一部分（大小写不同） | 只显示匹配账号；无匹配时提示 |
| U-07 | P1 | 关闭“自动确定日期和时间” | 列表顶部出现时间警告 |
| U-08 | P1 | 添加 20 个以上账号后滚动 | 流畅，无卡顿；按服务名排序 |

## 4. 编辑与删除

| ID | 优先级 | 步骤 | 预期 |
|---|---|---|---|
| E-01 | P0 | 编辑服务名并保存，返回列表 | 列表显示新名称；验证码不变 |
| E-02 | P0 | 编辑页不显示当前密钥；输入新密钥 `GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ` 保存 | 验证码随之改变并与 `oathtool` 一致 |
| E-03 | P1 | 编辑页修改位数为 8 | 页面有参数修改警告；保存后显示 8 位 |
| E-04 | P0 | 删除账号：先取消，再确认 | 取消时不删除；确认后从列表消失，重启后仍不存在 |

## 5. 数据与系统

| ID | 优先级 | 步骤 | 预期 |
|---|---|---|---|
| S-01 | P0 | 重启手机后打开 | 需要解锁；所有账号仍在 |
| S-02 | P0 | 截图、录屏、最近任务缩略图（锁屏页和列表页各一次） | 均为黑屏或被系统阻止 |
| S-03 | P0 | 厂商换机 / 本地备份工具（如小米“手机搬家”、华为“手机克隆”、OPPO“手机搬家”）迁移到另一台设备 | 不迁移 App 数据；若迁移，新设备显示“无法读取数据”，且不覆盖原文件 |
| S-04 | P0 | Google 备份（有 GMS 的设备）：`adb shell bmgr backupnow io.github.yozedens.secureauth` | 不产生 App 数据备份 |
| S-05 | P1 | 低内存 / 后台清理后恢复 | 必须重新解锁，不崩溃 |
| S-06 | P1 | 深色模式、系统字体放大到最大 | 可读、无截断导致的功能不可用 |
| S-07 | P1 | 平板或折叠屏展开 / 折叠 | 布局正常，锁状态不变 |
